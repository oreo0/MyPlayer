# MyPlayer — 构建 44（基于构建 39：选择卡顿与内存优化）

从构建 39 恢复；不含 40–43 的顶栏分组、显隐或英文支持。状态栏歌词改用系统默认菜单栏字号与常规字重，垂直居中和固定宽度保持。

选中高亮改用 NSTableRowView 原生背景，按需更新不同颜色的可见行，不再添加高亮子视图、逐行要求重绘或要求整表重绘。去掉 NativeTableDensity 的持续 KVO 反向写入，仅在绑定时配置初始紧凑行高，避免与 SwiftUI 的布局更新相互触发。滚动歌名使用原生文本和 Core Animation，取消逐帧 SwiftUI 状态动画。

曲库封面无损保存到用户数据 Artwork 文件夹，以 SHA256 去重。library.json 仅保存文件引用；旧的内嵌数据保持兼容，迁移前保留 library-before-artwork-migration.json。文件写入并核验完成后才释放内嵌封面；损坏或无法写入时保留原内嵌数据。元数据编辑、喜欢状态及移除记录不被迁移快照覆盖，迁移在后台执行。导入到新数据目录时修复封面引用路径。

封面缓存使用轻量身份字符串而非原始图片作为键，总成本限额8MB；任务标识不再散列大型图片数据。仅显示的播放页保留大封面/背景位图，隐藏后释放。播放页大封面下采样上限1536像素，列表缩略图96像素，大封面网格320像素。取色采样改为小缩略图，避免解码完整封面用于取色。

音频与视频共用 AVPlayer 流式播放、进度和系统控制，保留队列/单曲模式与会话恢复。视频取色使用原生 NV12 平面稀疏采样，避免额外完整 BGRA 帧转换；暂停、后台或无需取色时移除附加输出，活动采样间隔2.5秒。

取消右侧面板底栏与播放页底栏的位置/大小过渡动画；保留其他显隐行为。

验证：200次离屏原生表格选中无附加高亮子视图；2,000次相同歌名更新无动画重建；封面无损/去重/损坏保护及备份；32项测试曲库JSON由22,376,909字节降为13,101字节；独立曲库加载进程物理内存41,648,680字节降为2,458,128字节。上述内存是相同合成曲库的隔离加载测试，非整个应用实际播放占用。真实WAV和QuickTime视频恢复、歌词同步/播放策略、数据迁移保护、快捷键、排序及封面几何回归通过。用户媒体的实际CPU和内存还需复测。

首次运行会后台迁移旧封面；原封面和旧曲库备份保留。安装前完全退出旧 MyPlayer，再替换应用。

# MyPlayer — 构建 39（播放状态恢复、统一状态栏、DMG）

当前媒体和播放进度保存在固定用户数据目录，和应用包、构建编号无关。切歌、暂停/继续、拖动进度、关闭及退出保存，播放时约每秒写一次原子检查点；闪退后的恢复点是最近成功写入的检查点。下次打开恢复音乐/视频、进度、暂停/播放状态和原播放上下文。媒体暂时不可访问时保留记录并提示，不把曲库排除项目重新导入。显式移除当前播放项目会清除恢复记录。

# MyPlayer — 构建 31（封面侧栏与视频歌词试用）

右侧歌词面板复用“封面歌词背景”开关，按封面独立计算亮暗和强调色，并同步其悬浮底栏。无封面时回退应用外观，不改变主曲库和队列的外观。侧栏封面背景使用与自身亮暗相匹配的遮暗程度，原正在播放页面的背景处理保留。

视频可手动匹配 LRC/SRT/VTT，或读取同目录同名文件；通过顶部歌词按钮启用独立的黑色下方歌词区（不覆盖视频），此时隐藏底栏，视频保持完整适配。菜单“视频歌词”提供居中单行/KTV双行左右分离，独立字号28–72和字重，字体固定白色。字幕/歌词时间与原歌词同步偏移一致；KTV填充按句子起止时间插值，普通LRC没有逐字时间时不宣称精确逐字同步。视频表面保持同一个AVPlayerView，切换歌词区不重建播放引擎。

修复自动切歌先消费队列而绕过单曲循环的问题。播放模式先于队列处理，单曲播放暂停不消费队列，单曲循环保留队列并重播，列表循环推进队列；手动上下首仍可切歌。合集播放不再强行重置为列表循环，过期音频/视频结束回调不再推进当前新曲目。
